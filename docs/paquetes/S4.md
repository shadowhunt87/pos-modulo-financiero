## 2. Objetivo
Pantallas para: activar el 2FA con QR y guardar los códigos de emergencia; entrar con código; inscribirse al entrar cuando la empresa lo exige; cambiar de teléfono, regenerar y desactivar; confirmar las acciones delicadas del ADMIN; ver los «Cambios de seguridad», y «Exportar todos mis datos» (solo ADMIN). Cualquier persona debe poder hacerlo sin capacitación (P7, P10, R12).

## 5. No hagas
- No cambies el backend (si falta un endpoint, para y avisa). No guardes el desafío, los secretos ni los códigos en `localStorage`.
- No cambies la CSP (`frontend/deploy/security-headers.conf`).
- No trates un 422 de confirmación como sesión vencida. No uses `Number()` para dinero. No uses datos reales.

## 6. Pasos sugeridos
1. Interceptor, tipos y `downloadPost`.
2. Login en dos pasos + inscripción («Paso 1 de 3…») + «Perdí mi teléfono».
3. «Seguridad de mi cuenta»: estado con **fecha e IP de activación**; Activar (paso 1: qué aplicación instalar, con enlaces a las tiendas oficiales de Google Authenticator y Microsoft Authenticator); Cambiar de teléfono; Regenerar; Desactivar (oculto si el rol lo exige).
4. Códigos de emergencia: una sola vez, «Copiar», «Descargar .txt», «Guárdalos ahora».
5. Usuarios: diálogo de confirmación reforzada reutilizable (clave + código si hay 2FA) y bloque de cambios de seguridad (el rescate se muestra como «operador del sistema»).
6. Exportación: qué incluye y qué no (sin papeles de la auditora, D47), tamaño estimado, aviso de datos sensibles, confirmación, «Me voy del servicio», estado de descarga.
7. Patrón de Fase 1: migas, línea de propósito, `app-field-help`, `app-error-notice`, «?» con su entrada en `ayuda.json`; 375 px y teclado.
8. nginx, `ayuda.json` y manual; corre `verificar-ayuda`.

## 7. Criterios de aceptación
- Un usuario sin 2FA activa el 2FA, sale y vuelve a entrar con clave + código; también entra con un código de emergencia y ve cuántos le quedan. Un usuario sin 2FA entra como siempre.
- Una clave o un código mal escritos en cualquier confirmación (perfil, usuarios, exportación) muestran el error **sin cerrar la sesión**.
- Los códigos de emergencia se ven una sola vez (al recargar no vuelven).
- Inscripción obligatoria y el 403 «tu empresa exige…» se explican con «cómo arreglarlo».
- El rescate aparece como «Restablecido por el operador del sistema».
- Exportar solo aparece para ADMIN (los demás no ven la opción; por URL, «No tienes permiso»); el ZIP abre en Windows y macOS.
- `node scripts/verificar-ayuda.mjs` sin errores; checklist de GUIA-PRODUCTO §6 en cada pantalla nueva.

## 8. Cómo probar
```
cd frontend && npm ci
npx ng build
npx ng test            # si se queda esperando cambios: npx ng test --watch=false
node scripts/verificar-ayuda.mjs
```
Para ver las pantallas con el backend real: levanta el backend con tu base propia (ficha S1 §8) y `npm start` en `frontend/` (usa `proxy.conf.json`).

## 10. Riesgos y trampas
- Es la entrada al sistema: un error aquí bloquea a todos. Prueba el login normal además del nuevo.
- El interceptor es la trampa principal: un 401 mal tratado expulsa al ADMIN en medio de una confirmación.
- `/login` no necesita «?» propio, pero sí está en `pantallas`.
- La ayuda de campo se oculta con «Ocultar ayudas»; los errores nunca.
- Seguridad revisa el flujo completo antes de abrir la puerta de datos reales.
