## 2. Objetivo
Pantallas para: activar el 2FA con QR y guardar los códigos de recuperación, entrar con código, desactivarlo, y «Exportar todos mis datos» (solo ADMIN). Cualquier persona debe poder hacerlo sin capacitación (P7, P10, R12).

- **Modificar:** `features/auth/login.ts` (segundo paso: código o código de recuperación), `core/auth.ts` (manejar la respuesta de «falta el código»), `features/admin/profile.ts` o una pantalla nueva `features/security/` (activar/desactivar 2FA; según el anexo), `features/admin/admin.routes.ts` (rutas nuevas con `roleGuard('ADMIN')` para exportar).

## 5. No hagas
- No cambies el backend (si falta un endpoint, para y avisa). No guardes secretos ni códigos en `localStorage`.
- No cambies la CSP (`frontend/deploy/security-headers.conf`) sin avisar a seguridad.
- No uses `Number()` para dinero. No uses datos reales.

## 6. Pasos sugeridos
1. Lee el login actual y cómo `Auth` guarda el token. Dibuja el flujo de pantallas (activar → mostrar QR → confirmar con un código → mostrar los códigos de recuperación **una sola vez**).
2. Login en dos pasos: un campo de código claro, enlace «Usar un código de recuperación», error con `app-error-notice`.
3. Pantalla de seguridad de la cuenta: estado (activado/desactivado), activar, desactivar, regenerar códigos.
4. Pantalla de exportación (ADMIN): explica qué incluye, botón único, estado de descarga, aviso de que contiene datos sensibles.
5. Aplica el patrón de Fase 1: migas, línea de propósito, `app-field-help`, `app-error-notice`, estado vacío/explicación, «?» con su entrada en `ayuda.json`.
6. Revisa a 375 px y con teclado (Tab, Enter guarda, Esc cierra).
7. `ayuda.json` + manual; corre `verificar-ayuda`.

## 7. Criterios de aceptación
- Un usuario sin 2FA activa el 2FA, sale, vuelve a entrar con clave + código.
- Códigos de recuperación visibles una sola vez, con botón de copiar y aviso «guárdalos ahora».
- Código incorrecto: mensaje en español con «cómo arreglarlo» (no el texto técnico del servidor).
- Exportar solo aparece para ADMIN (los demás no ven la opción; por URL ven «No tienes permiso»).
- `node scripts/verificar-ayuda.mjs` termina sin errores (toda ruta nueva mapeada en `pantallas`).
- Checklist de GUIA-PRODUCTO §6 completo para cada pantalla nueva.

## 8. Cómo probar
```
cd frontend && npm ci
npx ng build
npx ng test            # si se queda esperando cambios: npx ng test --watch=false
node scripts/verificar-ayuda.mjs
```
Para ver las pantallas con el backend real: levanta el backend con tu base propia (ver ficha S1 §8) y `npm start` en `frontend/` (usa `proxy.conf.json`).

## 10. Riesgos y trampas
- Es la entrada al sistema: un error aquí bloquea a todos. Prueba el login normal (sin 2FA) además del nuevo.
- `/login` no necesita «?» propio (el verificador lo ignora), pero sí está en `pantallas`.
- `core/errors.ts` traduce mensajes; mensajes nuevos del servidor deben tener su patrón en `ayuda.json` → `errores`.
- La ayuda de campo se oculta con «Ocultar ayudas»; los errores nunca.
- Seguridad revisa el flujo completo antes de abrir la puerta de datos reales.
