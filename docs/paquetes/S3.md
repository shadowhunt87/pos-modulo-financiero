# S3 — Copia de respaldo fuera del servidor, cifrada

**Carril:** S · **Nivel:** N2 (devops) · **Tamaño:** M · **Ola:** 2 · **Rama:** `wp/S3-copia-externa` · **Asignado (provisional):** IA-S
**Espera a:** **D17 y D18 de Carlos** (D17: a qué destino se sube la copia; D18: quién guarda la frase secreta). Sin esas dos respuestas **no se programa el destino ni se crea ninguna frase**. Lo que sí se puede preparar antes: cifrado local, aviso de fallo y la prueba de restauración.
**Ficha del 2026-10-12** · PLAN-v0.3 v1.2 tarea 3.3, PLAN-v0.2 §11.2.

## 2. Objetivo
Cada respaldo diario sale del servidor **ya cifrado**, avisa si falla y se comprueba que se puede restaurar **desde la copia externa**. Así, si el servidor se pierde, los datos no se pierden (R12, P10; condición para datos reales).

## 6. Pasos sugeridos
1. Lee `backup.sh`: hoy hace `pg_dump`, tar de adjuntos, sha256, publica solo si todo salió bien y llama a `OFFSITE_CMD`.
2. Añade el cifrado (el plan propone `gnupg`, simétrico, con la frase tomada de un archivo con permisos 600 fuera del repo). Mantén los sha256 del archivo cifrado.
3. Ajusta la retención y los nombres (`db-*.dump.gpg`, etc.) sin romper `prune` ni `restore-test.sh`.
4. Escribe el aviso de fallo: archivo de estado + `backup-status.sh`; que el log diga FALLA con claridad.
5. Haz que `restore-test.sh` pueda partir de la copia **externa** descargada (o de una carpeta que simule el destino) y verifique: conteos por tabla, balanza que cuadra por empresa, un adjunto que abre.
6. Documenta el paso a paso para Carlos (D17/D18 pendientes quedan como «completar cuando Carlos decida»).
7. Prueba con carpetas temporales: respaldo → cifrado → «subida» a una carpeta local → restauración → resultado OK; y un caso donde el comando externo falla.

## 7. Criterios de aceptación
- Un respaldo nuevo produce archivos cifrados; abrirlos sin la frase falla; con la frase, `pg_restore --list` funciona.
- Si `OFFSITE_CMD` falla, el script sale con error **y** el respaldo local queda guardado (comportamiento actual).
- `backup-status.sh` devuelve error con un respaldo de más de 26 h y OK con uno de hoy.
- `restore-test.sh` termina en `RESULTADO: OK` partiendo de la copia cifrada, y en FALLA si falta la frase o el archivo está dañado.
- Ninguna salida (log, consola) contiene la frase.
- `docs/OPERACION-BACKUPS.md` tiene el paso a paso completo para Carlos.

## 8. Cómo probar
Sin Docker de la app: carpetas temporales y un Postgres local de pruebas.
```
BACKUP_DIR=$(mktemp -d) scripts/backup.sh        # ver cómo toma COMPOSE_PROJECT; ajusta a tu entorno de prueba
BACKUP_DIR=<la misma> scripts/restore-test.sh
shellcheck scripts/*.sh                           # si lo tienes
```
Si tu entorno no puede correr los scripts (dependen del contenedor `financiero-pruebas-postgres-1`), dilo en el PR y entrega pruebas con un Postgres propio.

## 10. Riesgos y trampas
- Si se pierde la frase, **todos** los respaldos quedan inservibles (PLAN-v0.2 §20.2): el documento debe decirlo con letras grandes.
- `restore-test.sh` busca `db-*.dump` y compara conteos de `User, Company, Partner, Invoice, JournalEntry, AuditLog`; con archivos cifrados hay que adaptarlo.
- El gancho `OFFSITE_CMD` recibe `BACKUP_DB`, `BACKUP_ADJUNTOS`, `BACKUP_SHA`: cuida las rutas con espacios.
- `gnupg`/`rclone` pueden no estar instalados en el servidor: pregúntalo en el PR, no lo asumas.
- Seguridad revisa este paquete (cifrado, permisos de carpeta, frase fuera del servidor).
