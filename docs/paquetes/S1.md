## 2. Objetivo

## 6. Pasos sugeridos
1. Lee el anexo y haz una tabla «decisión → archivo que la implementa».
2. Esquema + migración (aditiva; si agregas un valor a `AuditAction`, va en **su propia** migración). `npx prisma generate`.
3. Servicio de 2FA: generar secreto, verificar código, códigos de recuperación (hash, uso único), cifrado del secreto.
4. Login en dos pasos: sin 2FA activo todo sigue igual; con 2FA devuelve un desafío corto y un segundo endpoint entrega el token final.
5. Límite de intentos del código con `AttemptLimiter`; `writeAudit` en cada acción (activar, desactivar, usar recuperación, restablecer por ADMIN).
6. Restablecer 2FA por ADMIN (solo de usuarios de su empresa; 404 si es de otra); invalida sesiones como el reseteo de clave.
7. Escribe `test/two-factor.e2e-spec.ts` y ajusta `security.e2e-spec.ts` si las rutas nuevas lo exigen.
8. Corre toda la suite; pasa `npm audit` si agregaste librería.

## 7. Criterios de aceptación
- Usuario sin 2FA entra como hoy (las 370 pruebas actuales siguen en verde).
- Con 2FA: clave correcta + sin código → no recibe token final; con código correcto → sí; código usado dos veces → rechazado; código fuera de la ventana → rechazado.
- Código de recuperación: sirve una sola vez; al usarlo queda en `AuditLog`.
- 5 códigos malos seguidos → bloqueo temporal (mismo límite que el login).
- ADMIN restablece el 2FA de un usuario de su empresa; de otra empresa → 404; APPROVER/ACCOUNTANT/VIEWER → 403.
- Tras restablecer, los tokens anteriores del usuario dejan de servir.
- Ninguna respuesta incluye secreto, hash ni códigos (salvo la entrega única al activar).
- `test/security.e2e-spec.ts` en verde (rutas con roles explícitos; solo las excepciones que el anexo autorice).

## 8. Cómo probar
```

docker run -d --name pg-S1 -e POSTGRES_PASSWORD=<clave-local-inventada> -e POSTGRES_DB=fin_s1 -p 55432:5432 postgres:18-alpine
# En TU .env local (no se sube): DATABASE_URL=postgresql://postgres:<clave>@localhost:55432/fin_s1
#   JWT_SECRET=<salida de: openssl rand -hex 64>   UPLOADS_DIR=./uploads-s1
npm ci && npx prisma migrate deploy && npx prisma generate
npm run build && npm test && npm run test:e2e
```
Si ya existe un `.env` en tu copia, no lo abras ni lo copies: crea el tuyo.

## 10. Riesgos y trampas
- **Alto riesgo** (inicio de sesión): seguridad revisa este PR sí o sí.
- La prueba «Política de rutas» exige `@Roles` en toda escritura; hoy solo 3 rutas están abiertas. Una ruta nueva sin roles hace fallar la suite.
- `AuditAction` es un enum de Postgres: agregar valores requiere migración propia y el cliente generado (`src/generated` no se versiona).
- Los tokens llevan `iat`: al cambiar el 2FA hay que decidir si se invalidan (`passwordChangedAt`).
- Sincronía de reloj y reutilización de códigos TOTP: prueba con reloj simulado.
- Cuidado con revelar si el correo existe (el login actual usa un hash falso para igualar tiempos).
